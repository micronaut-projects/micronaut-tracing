RabbitMQ / AMQP tracing is supported by the `micronaut-tracing-opentelemetry-rabbitmq` module.

Add the dependency to enable OpenTelemetry tracing for Micronaut RabbitMQ publishers and listeners.

dependency:micronaut-tracing-opentelemetry-rabbitmq[scope="implementation", groupId="io.micronaut.tracing"]

The module creates producer spans for `@RabbitClient` publications, injects the active trace context into AMQP headers, and creates consumer spans for `@RabbitListener` deliveries after extracting that propagated context.

The consumer span covers the dispatch of a delivery by the RabbitMQ consumer. When a listener runs on the consumer thread (the default), the span therefore also covers the listener method.
When a listener is configured with an executor (for example `@RabbitConnection(executor = "...")`), the delivery is handed off to that executor and the consumer span ends once the work has been submitted. The span context is exposed through Micronaut's `PropagatedContext` during dispatch, so an executor that propagates the Micronaut context (for example one that wraps submitted tasks with `PropagatedContext.wrapCurrent(..)`) runs the listener in the delivery's trace context, and any spans created by the listener become children of the consumer span.

RPC reply consumers that Micronaut RabbitMQ registers on the `amq.rabbitmq.reply-to` pseudo-queue are not traced separately; the reply is covered by the producer span of the request.

Instrumentation is enabled by default and can be disabled with:

[configuration]
----
otel:
  instrumentation:
    rabbitmq:
      enabled: false
----

Wrapper-based instrumentation for Micronaut RabbitMQ publishers and channel pools is enabled by default.
To keep the RabbitMQ telemetry bean available but disable wrapper registration, set:

[configuration]
----
otel:
  instrumentation:
    rabbitmq:
      wrapper: false
----
